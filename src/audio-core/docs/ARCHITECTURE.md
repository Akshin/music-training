# audio-core — архитектура

Ядро для записи, анализа и синтеза звука в тренажёре для музыкантов — голоса и любых инструментов. Живёт в `audio-core/` как
самостоятельная папка без `package.json`; переезжает переносом папки. Этот документ — журнал
решений (ADR) и карта кода. Код и комментарии — на английском, документация — на русском.

## Принципы

1. **Ядро не знает платформы.** `core/` компилируется с `lib: ["ES2023"]` и `types: []` — любой
   `window`, `AudioContext`, `navigator`, `Buffer` не проходит компиляцию
   (`tsconfig.core.json`). Импорты из `io/`, `host/`, приложения и UI-стека запрещены ESLint
   (`eslint.config.ts`, блок `audio-core/boundaries`). Один и тот же код работает в воркере, в
   главном потоке, в Node и офлайн по файлу.
2. **Ноль runtime-зависимостей.** FFT, YIN, LPC, окна, фильтры — свои, за интерфейсами. WASM —
   только если профилировщик попросит.
3. **Ноль аллокаций в горячем цикле.** Буферы выделяются при создании; результаты кадра —
   переиспользуемые объекты и typed arrays.
4. **Каждая величина с достоверностью и валидностью.** `NaN` — «не применимо» (f0 на неозвученном
   кадре); `confidence` — отдельная колонка.
5. **Realtime и offline — одни примитивы.** Стриминговый проход пишет кадры; офлайновый проход
   уточняет их по сохранённому PCM с lookahead.
6. **Рендеринг — не часть ядра.** Ядро выдаёт модель данных; график — потребитель.

## Слои и правило зависимостей

```
audio-core/
  core/                 платформонезависимое ядро (без DOM и Node)
    model/              AudioChunk, Timeline, NoteEvent, питч-утилиты
    clock/              BeatGrid — музыкальное время (доли ↔ секунды); TempoMap — смена темпа/размера
    dsp/                Fft/RealFft, окна, уровень, парабола, Yin, biquad, K-weight, Burg LPC
    analysis/           контракт экстрактора, граф, FrameBuffer, Analyzer, registry, extractors/
    transport/          протокол сообщений, BufferPool, FrameBatcher, TimelineMirror — без DOM
    session/            PcmTape (горячее кольцо + холодные int16), WAV, Session/Take, офлайн-проход
    segmentation/       паузы → фразы → ноты (greedy или Mauch 2015) и слайды; жесты питча
    synthesis/          PCM щелчка и тона, metronomeClicks, referenceTriggers
    scoring/            онсеты, estimateLatency, scoreTake (питч / ритм / уровень)
    testing/            генераторы сигналов и сравнение контуров — только для тестов
    index.ts            публичная поверхность
  io/                   источники: MicSource, LineInSource, FileSource, StreamSource
  host/web/             capture.worklet, analysis.worker, WorkerHost, WebSynth, WebTransport, WebLoop
  docs/                 этот документ
```

Правило: `core/*` никогда не импортирует `io`, `host`, приложение. Проверяется компилятором и
линтером, а не дисциплиной.

Пять tsconfig — по одному на глобальную область видимости:

| Конфиг                  | Файлы                           | lib / types                       |
| ----------------------- | ------------------------------- | --------------------------------- |
| `tsconfig.core.json`    | `core/**` без тестов            | ES2024, `types: []`               |
| `tsconfig.test.json`    | `core/**` с тестами             | + `node`                          |
| `tsconfig.web.json`     | `core`, `io`, `host/web` (main) | + DOM, `vite/client`; эмитит d.ts |
| `tsconfig.worker.json`  | `core`, `*.worker.ts`           | ES2024 + WebWorker                |
| `tsconfig.worklet.json` | `core`, `*.worklet.ts`          | ES2024 + `@types/audioworklet`    |

Приложение ссылается на `tsconfig.web.json` как на project reference и видит только его `.d.ts`
(`node_modules/.tmp/audio-core-web`): ядро проверяется своими правилами (без
`noUncheckedIndexedAccess` — в DSP это `!` на каждом индексе), приложение — своими.

Синтез и оценка живут в ядре как чистые функции: host только проигрывает уже готовый PCM и
спрашивает `BeatGrid` про окно lookahead. Калибровка латентности — в `/lab` (M4).

## Модель данных

Пять уровней, у каждого свой темп и задержка:

| Уровень  | Что                                                   | Темп                                | Где                                                   |
| -------- | ----------------------------------------------------- | ----------------------------------- | ----------------------------------------------------- |
| Сигнал   | PCM `AudioChunk { samples, startSample, sampleRate }` | семплы                              | Recorder (M3)                                         |
| Кадры    | скаляры на кадр: f0, rms, cents, форманты…            | hop 10 мс                           | `Timeline`                                            |
| Контур   | сглаженный f0, вибрато, жесты питча                   | окно по кадрам, задержка 100–500 мс | `vibrato`, `formants`, `loudness`, `classifyGestures` |
| Сегменты | паузы, фразы, ноты                                    | события                             | `Timeline.events` (M3)                                |
| Сессия   | диапазон, статистика, сравнение с референсом          | офлайн                              | `session/`, `scoring/` (M3–M4)                        |

### Timeline

Колоночное append-only хранилище: по `Column` на фичу, блоки `Float32Array` по 4096 кадров,
рост без копирования. Незаписанная ячейка читается как `NaN`. 40 минут при 100 кадрах/с и
~24 колонках ≈ 23 МБ.

Кадр `i` относится к моменту `(originSample + i · hopSize) / sampleRate` — **центру окна анализа**,
а не его началу. Это проверяется тестом: контур вибрато, снятый анализатором, совпадает с истиной
без временного сдвига (подбор δ даёт 0.00 мс).

### NoteEvent

`{ midi, startBeat, durationBeats, velocity? }` — один тип и для того, что играет синтез
(референс-мелодия), и для цели, с которой сравнивает оценка. Расходиться им негде.

## Граф экстракторов

Экстрактор — синглтон `defineExtractor({ id, deps, columns, create(ctx, options) })`.
`deps` ссылаются на другие определения (типизированный `results.get(dep)`), `columns` — скаляры
в таймлайн, результат `create().process()` — эфемерный объект кадра для зависимых и слушателей
(например, буфер спектра). `Analyzer` резолвит запрошенный набор в топологический порядок,
дедуплицирует по объекту, отвергает конфликты id и колонок, циклы. Опции передаются по id:
`createAnalyzer(config, [pitch], { pitch: { a4: 442 } })`.

Реализовано в M1:

| id          | deps             | колонки                                            | результат                                                  |
| ----------- | ---------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| `spectrum`  | —                | —                                                  | `magnitude[frameSize/2+1]`, нормировка: полный синус ≈ 1.0 |
| `level`     | —                | `rms`, `dbfs`, `peak`                              | то же                                                      |
| `f0`        | —                | `f0` (Гц или NaN), `f0Confidence`                  | YIN; опция `tracker: 'pyin'` (лаг 5 кадров)                |
| `pitch`     | `f0`             | `midi`, `note`, `cents`                            | A4 настраиваемый                                           |
| `vibrato`   | `f0`             | `vibratoRate`, `vibratoExtent`                     | 500 мс, ACF 4–12 Гц; extent / sinc(rate·окно)              |
| `formants`  | `f0`             | `f1`, `f2`, `f3`                                   | Burg LPC ~10 кГц, корни Durand–Kerner                      |
| `loudness`  | —                | `lufsMomentary`, `lufsShortTerm`, `lufsIntegrated` | K-weight; integrated = −70 + относительный −10 LU          |
| `cpp`       | `f0`             | `cpp`                                              | Hillenbrand 1994, dB; NaN на неозвученном                  |
| `onset`     | `spectrum`       | `onsetStrength`                                    | Superflux (Böck): max-filter по частоте, затем flux        |
| `harmonics` | `f0`, `spectrum` | `h1`, `h2`, `h3` (dBFS)                            | пик у k·f0 ± f0/3, парабола по dB; NaN на неозвученном     |

### Analyzer

`push(chunk | Float32Array)` → кадры. Окно 2048 (43 мс при 48 кГц), hop `round(sampleRate/100)` →
ровно 100 кадров/с и на 44.1, и на 48 кГц. Часы сессии — счётчик доставленных семплов; разрыв в
`startSample` заполняется нулями (время не дрейфует), перекрытие отбрасывается; оба считаются в
`getStats()`. `onFrame(listener)` — точка подключения транспорта в воркер и живой картинки.

## Время и клок

Мастер-часы в браузере — `AudioContext.currentTime`; `performance.now()` и `setInterval`
дрейфуют относительно аудио. Захват штампует чанки семпл-позицией на этих часах. `BeatGrid`
переводит доли ↔ секунды; от него зависят и планировщик метронома (`WebTransport`, lookahead по
Chris Wilson «A Tale of Two Clocks»), и оценка ритма — они согласны по построению. Латентность
ввода калибруется (щелчок → запись → сдвиг), без этого оценка ритма в мс — фикция.

## Потоки и транспорт

```
audio thread            worker                        main
capture.worklet ──pcm──▶ analysis.worker ──frames──▶ WorkerHost → TimelineMirror → Timeline
       ▲   recycle-pcm ◀──┘        ▲     recycle-frames ◀──┘                        │
       └── MessageChannel (port) ──┘                                        UI читает slice()/latest()
```

- **Ворклет** (`host/web/capture.worklet.ts`) только копирует 128-семпловые кванты в батч
  (512 семплов = 10.7 мс при 48 кГц) и штампует его `startSample` по `currentFrame` — часам
  аудиоконтекста. Пустой вход (нет каналов) пишется нулями, чтобы часы не ломались. Никакого DSP.
- **PCM идёт в воркер напрямую**: главный поток создаёт `MessageChannel`, один порт отдаёт
  ворклету (`connect`), второй — воркеру. Главный поток не просыпается на каждый батч.
- **Воркер** (`analysis.worker.ts`) держит `Analyzer`; фичи приходят строковыми id и
  резолвятся через `analysis/registry.ts` — определения экстракторов через границу не проходят.
  Новые кадры после каждого push уходят батчами (`FrameBatcher`, до 64 кадров, один Float32
  буфер на колонку + снимок спектра по запросу).
- **Главный поток** (`WorkerHost`) строит такой же `Timeline` из тех же id (геометрия совпадает
  по построению), применяет батчи через `TimelineMirror` и возвращает буферы (`recycle-frames`).
  PCM-буферы воркер возвращает ворклету пачками по 8 (`recycle-pcm`).
- Всё — transferable `ArrayBuffer` с **пулом** (`BufferPool`): в установившемся режиме ни одна
  сторона не аллоцирует. Измерено на `/lab`: 8 буферов на 8 колонок, `free/allocated = 8/8`
  спустя минуты работы. SharedArrayBuffer требует COOP/COEP, которых GitHub Pages не даёт.
- Протокол (`core/transport/protocol.ts`) — чистые данные, компилируется во все три области
  видимости; тесты транспорта гоняют `structuredClone` с transfer-листом как настоящий
  `postMessage`.

Стоимость сообщений при 48 кГц: ~94 PCM/с в воркер, ~12 recycle/с назад, ~94 frames-батча/с
на main (по 1–2 кадра) и столько же recycle. Все — мелкие; главный поток занят только зеркалом.

### MicSource

`getUserMedia` с `echoCancellation/noiseSuppression/autoGainControl: false`, `channelCount: 1`,
после чего `track.getSettings()` показывает, что браузер применил на самом деле —
`MicSourceInfo.processing` и флаг `processed`; UI обязан предупреждать. Контекст
`latencyHint: 'interactive'`; ворклет-нода имеет один тихий выход в `destination` — иначе часть
браузеров не вызывает `process()`. Модуль ворклета подключается через `?worker&url` (Vite
собирает его отдельным файлом; это единственная зависимость движка от сборщика, изолирована в
`host/web/capture-worklet-url.ts`).

## Хранение 40-минутной сессии

- PCM: `PcmTape` — горячее кольцо 120 с float32 (~23 МБ) и холодные чанки int16 по 10 с.
  В воркере холодный бэкенд — OPFS (`createSyncAccessHandle`); если его нет, чанки остаются в
  памяти. 40 мин int16 ≈ 230 МБ. Часы ленты совпадают с анализатором: разрывы — нули, перекрытия
  отбрасываются.
- Скаляры таймлайна — в памяти целиком (~23 МБ).
- Спектр не хранится (1 ГБ за сессию): живой снимок приходит с батчем кадров; пересчёт из PCM
  по запросу — позже, вместе с обзорной спектрограммой.
- `Session → Take[]`: именованные диапазоны на ленте; приложение ставит маркеры упражнений.
- Экспорт: `tapeToWav` / `WorkerHost.exportWav()` — mono 16-bit WAV. Офлайн-проход `analyzeTape`
  гоняет тот же `Analyzer` по ленте; на синусе 220 Гц расхождение f0 с живым проходом < 1 цента.

## Сегментация

`segmentTake(timeline)` — чистая функция колонок `dbfs` / `midi` / `f0Confidence`:

1. **Фразы** — адаптивный гейт (10-й перцентиль уровня + 15 дБ, не ниже −65 dBFS), короткие
   паузы склеиваются, клики короче 120 мс отбрасываются.
2. **Ноты (greedy, по умолчанию)** — жадный проход по контуру с полосой ±60 центов и медианным
   центром; октавные блипы внутри ноты игнорируются. Смазанные хроматические «ноты» на легато
   (артефакт окна 43 мс) выкидываются, если они короче настоящей ноты и лежат между двумя более
   длинными.
3. **Слайды** — портименто, которое жадный проход нарезал лестницей, схлопывается обратно;
   вход в ноту классифицируется как `attack` / `legato` / `slide` / `gap`.
4. **Ноты (Mauch / Tony, `method: 'mauch'`)** — HMM: тишина + целые MIDI 36–84, наблюдение —
   гаусс по `midi` и гейт по `dbfs`/`f0Confidence`, полный Viterbi, ноты короче 80 мс
   отбрасываются. Слайдов нет; ноты вне фраз не попадают в результат. На `/lab` после Стоп и
   после файла.
5. **Жесты** — `classifyGestures(timeline, notes)` → `straight | vibrato | scoop | fall`. Не
   меняет `NoteSegment`.

Проверено на `noteSequence` (паузы, легато 150 мс, портименто, вибрато, клик); Mauch — на тех же
пяти нотах, легато и вибрато.

### Источники файла и потока (M7)

- **`analyzeWav`** в ядре: `decodeWav` → тот же `Analyzer`. 16-bit PCM без DOM.
- **`FileSource` (`io/file-source.ts`)** — WAV через ядро; mp3/ogg/прочее — `decodeAudioData`
  только в `io/`. Чанки — `chunkSamples`, в воркер через `WorkerHost.push`.
- **`StreamSource`** — нумерация семплов на часах сессии; сам устройства не открывает.
- **pYIN офлайн.** `pyinDelay: 0` — причинный MAP без истории на весь take (полный backward
  store на 40 мин был бы сотни мегабайт). Живой `/lab` оставляет лаг 5 кадров.

`/lab`: кнопка **Файл** гоняет тот же воркер без микрофона; после Стоп — ноты Mauch и жест
рядом с каждой.

## Синтез и оценка (M4)

Один `NoteEvent[]` и один `BeatGrid` для того, что слышит ученик, и для того, с чем сравнивает
оценка. Расходиться им негде.

- **PCM в ядре.** `renderClick` — два затухающих партиала, три уровня: `bar` (пик 0.72), `group`
  (0.58), `beat` (0.45); `renderTone` — мягкое электропиано: двухоператорная FM с отношением 1,
  индекс модуляции спадает за ~0.1 с (яркая атака оседает к основному тону), затухание как у
  клавиши, хвост `TONE_RELEASE_SECONDS` = 150 мс после записанной длительности. Host (`WebSynth`) только кладёт эти
  семплы в `AudioBuffer` и ставит `AudioBufferSourceNode.start(when)` на
  `AudioContext.currentTime`. Ворклет синтеза не делает.
- **Акценты.** `metronomeClicks` ставит `level`: сильная доля, начало группы, прочие доли.
  Сложные размеры (6/8, 9/8, 12/8) группируют восьмые по три (`beatsPerGroup`), остальные — одна
  группа на такт.
- **Темп на лету.** `TempoMap` — сегменты `BeatGrid`; `change` вступает на первой доле не раньше
  запрошенного момента. Темп сохраняет нумерацию долей и тактов, размер открывает новую эпоху с
  сильной доли; ещё не наступившие изменения заменяются. `WebTransport.retime` зовёт его с
  курсором планировщика, `windows` режет окно lookahead по сегментам, `positionAt` отдаёт UI ту же
  сетку.
- **Референс на лету.** `WebTransport.setNotes(notes, epoch)` заменяет ноты без остановки. Доли
  нот считаются в эпохе `TempoMap`, окна другой эпохи их не играют. Note-on, попавшие в уже
  запланированный отрезок, досылаются сразу; повторов нет (ключ — эпоха, доля, высота).
  `setMetronome` включает и выключает щелчки, сетка идёт дальше. Кэш тонов `WebSynth` ограничен:
  каждый темп даёт новые длительности.
- **Записи.** `WebLoop` зацикливает декодированную запись (бэк-трек) на том же `AudioContext`:
  `decode` — `decodeAudioData` браузера (mp3/ogg/wav), `play(buffer, when)` — петля с плавным
  входом 0.6 с и одновременным уходом предыдущей, `stop` — плавный уход. Ядро записи не
  декодирует и не синтезирует; это не второй синтезатор, а проигрыватель готового контента.
- **Планировщики — чистые.** `metronomeClicks(grid, from, to)` и `referenceTriggers` отдают
  события окна. `WebTransport` спрашивает их каждые 25 мс на горизонт 100 мс (Chris Wilson);
  beat 0 = `audioOrigin` (старт + 80 мс).
- **Латентность.** `onsetTimes` — фронты `dbfs` выше гейта. `estimateLatency` — медиана
  (detected − expected): поглощает и I/O, и то, что транспорт стартовал позже захвата.
  В наушниках щелчок часто не попадает в микрофон; `/lab` тогда ставит программный сдвиг
  (время щелчка на аудиочасах ↔ `timeline.frameTime`).
- **scoreTake.** Питч — центы до целевого MIDI; ритм — онсет минус latency; уровень — среднее
  `dbfs` кадра против `20·log10(velocity)` (1 → 0 dBFS, 0.25 → ≈ −12). Непопавшие цели дают 0;
  `overall` — среднее питча и ритма, плюс уровень если он есть.

`/lab`: BPM/размер, метроном, C-мажор арпеджио (MIDI 60/64/67/72), калибровка, оценка после Стоп.

## Контур (M5)

Экстракторы с задержкой 300–500 мс поверх тех же кадров:

- **Вибрато.** Кольцо 50 кадров `f0` → центы вокруг медианы → автокорреляция в 4–12 Гц.
  Размах = `√2 · rms` (пик синуса), делённый на `sinc(rate · T_окна)`: окно 43 мс само
  ослабляет ±50 центов при 6 Гц до ~45 (теория 44.8); компенсация возвращает оценку к
  истинному экстенту. Ниже 18 центов — NaN, чтобы джиттер YIN на ровной ноте не считался
  вибрато.
- **Форманты.** Преэмфаза 0.97, ФНЧ, децимация к ~10 кГц, Hamming, Burg порядка ~12,
  Durand–Kerner, полюса 250–5500 Гц. На синтетическом /a/ (700 / 1200 / 2500) F1 и F2
  попадают в свои полосы.
- **LUFS.** K-фильтр libebur128/ITU (шелф 1.68 кГц + НЧ 38 Гц) по _новому хопу_, не по
  перекрытому окну анализа. Momentary 400 мс, short-term 3 с, порог −70. Смещение −0.691 дБ.
  Integrated — гейт EBU R128: сначала −70 LUFS, затем относительно `L − 10` LU.
- **`summarizeContour`** — средние по тейку; `/lab` показывает живую строку и сводку после Стоп.

### Глубина (M6)

- **pYIN.** Опция `f0: { tracker: 'pyin' }`. Локальные минимумы CMNDF в порядке лага (короткий
  период первым, как у YIN) получают массу Больцмана; остаток — состояние «неозвучено». Sparse
  Viterbi, лаг 5 кадров (~50 мс). На `/lab` включён по умолчанию; тесты YIN без опции не
  меняются.
- **CPP.** Cepstral peak prominence: IFFT log-спектра, пик в полосе 60–800 Гц минус линейный
  тренд. Гармонический тон ≫ шум.
- **Superflux.** `onsetStrength` — спектральный поток после max-filter по соседним бинам, чтобы
  вибрато не давал ложных онсетов. Калибровка латентности по-прежнему на `dbfs` (щелчки).
- **LineInSource** — то же, что MicSource: браузер не отличает линию от микрофона, устройство
  выбирается в `/lab`.

## Алгоритмы и источники

- **FFT** — radix-2 комплексный, f64-буферы, twiddle и bit-reversal предвычислены. Проверен
  против наивного DFT (1e-9).
- **YIN** (de Cheveigné, Kawahara 2002) — разностная функция через FFT-кросскорреляцию
  O(N log N), CMNDF, абсолютный порог 0.15 с спуском к локальному минимуму, парабола.
  **Отличие от учебника:** d(τ) усредняется по кадру и по его зеркальному отражению, поэтому
  центр измерения — ровно центр окна для любого τ. У классического YIN центр смещён на
  ~(W+τ)/2 от начала кадра, что при движении f0 читается как ошибка в центах (34 цента на
  вибрато ±100 при 6 Гц; после симметризации сдвиг 0.00 мс).
- **Окна** — Hann/Hamming/Blackman-Harris (periodic), Gaussian.
- **K-weighting** — ITU-R BS.1770-4, билинейное преобразование прототипов libebur128 (MIT).
- **LPC** — Burg; корни LPC-полинома — Durand–Kerner.
- **pYIN** — Mauch & Dixon 2014, фиксированный лаг Viterbi по CMNDF симметричного YIN.
- **CPP** — Hillenbrand, Houde & Cleveland 1994.
- **Superflux** — Böck, Krebs & Widmer 2012.
- **Ноты HMM** — Mauch et al., SMC 2015 (Tony): тишина + MIDI, Viterbi по контуру f0.

## Измеренная точность и производительность (M1)

Окно 2048, hop 480/441, синтетические сигналы, Node 24 / V8:

| Сигнал                                 | Ошибка f0                                                    |
| -------------------------------------- | ------------------------------------------------------------ |
| Синус 55–880 Гц, 48 и 44.1 кГц         | ≤ 0.34 цента (обычно < 0.1), confidence 1.00                 |
| Синус 1046.5 Гц (C6)                   | ≤ 0.49 цента                                                 |
| Гармонический тон 200 Гц, 10 партиалов | ≤ 0.02 цента                                                 |
| Свип 110→880 Гц за 6 с (600 центов/с)  | ≤ 0.40 цента                                                 |
| Вибрато 6 Гц ±50 центов                | сдвиг 0.00 мс, размах 46 из 50 (окно ослабляет: теория 44.8) |
| Вибрато 6 Гц ±100 центов               | сдвиг 0.00 мс, размах 94 из 100 (теория 89.6)                |
| Белый шум                              | confidence < 0.5 → unvoiced                                  |

Ослабление размаха вибрато — низкочастотный отклик окна 43 мс, `sinc(rate · window)`;
экстрактор `vibrato` делит измеренный экстент на этот коэффициент.

Пропускная способность: `f0` — 230 мкс/кадр (2.3 % реального времени), `f0 + pitch + level +
spectrum` — 267 мкс/кадр. YIN доминирует (6 FFT на кадр); запас для оптимизации ×2–3 без WASM.

Тесты фиксируют эти границы числами (`core/**/*.test.ts`).

### Живой тракт (M2)

Headless Chrome, `--use-file-for-fake-audio-capture` с WAV 220 Гц ±30 центов вибрато,
амплитуда 0.3: `/lab` показывает A3, 218–222 Гц, confidence 1.00, уровень −13.4 dBFS (теория
−13.47), 100 кадров/с, AEC/NS/AGC off, `baseLatency` 5.3 мс, пул 8/8 без роста. Первые 256
семплов после старта уходят в главный поток до `connect` и восполняются нулями (`gap 256`) —
таймлайн привязан к часам захвата, не к моменту подключения воркера.
